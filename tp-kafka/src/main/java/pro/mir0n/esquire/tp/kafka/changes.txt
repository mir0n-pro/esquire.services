06/15/2026 mir0n  v1.2.8 -- Kafka transport provider module
tp.kafka.TransportProvider  (new)
  - Kafka implementation of the transport-provider SPI; resolved by name (reflectively instantiated,
    no Spring bean) and owns its own audit producer / consumer.
  - openPublisher builds its own KafkaTemplate (String/String) from settings.endpoint() (bootstrap-servers)
    and sends each TransportMessage as a JSON value keyed by TransportMessage.key (per-entity order).
  - openConsumer runs a programmatic ConcurrentMessageListenerContainer; the consumer group-id comes from
    the provider param transport.kafka.group-id (PARAM_GROUP_ID, default esquire-xxrod-audit), read via
    settings.params(); auto-offset-reset earliest.
  - buildTemplate / buildConsumerFactory apply every leg param verbatim as a Kafka config; the essentials
    (bootstrap, serializers, group.id, client.id) win.
tp.kafka.TpKafkaAutoConfigFilter  (new)
  - AutoConfigurationImportFilter suppressing Boot's KafkaAutoConfiguration so a service that ships this
    provider stays transport-agnostic.
pom.xml  (new)
  - esquire-tp-kafka module; depends on esquire-common, spring-kafka, spring-boot-autoconfigure, slf4j-api.
META-INF/spring.factories  (new)
  - registers TpKafkaAutoConfigFilter as an AutoConfigurationImportFilter.
