Esquire Redis transport provider classes

06/15/2026 mir0n  v1.2.8 -- Redis transport provider module
tp.redis.TransportProvider  (new)
  - Redis-stream implementation of the transport-provider SPI; resolved by name (reflectively instantiated,
    no Spring bean) and owns its own audit stream connection. Producer-only (supportsConsume()=false; the
    stream IS the append-only log, read via XRANGE).
  - openPublisher XADDs each TransportMessage's header bag (plus stamped appl-msg-id + sending-time) to the
    destination stream as string fields (null fields omitted); approximate-trimmed to max-len when set.
  - openConsumer throws UnsupportedOperationException (no consume leg).
  - max-len comes from the provider param transport.redis.max-len (PARAM_MAX_LEN, default unbounded), read
    via settings.params(); buildTemplate builds a started StringRedisTemplate over a Lettuce connection,
    appending every leg param except max-len to the redis:// URI verbatim.
tp.redis.TpRedisAutoConfigFilter  (new)
  - AutoConfigurationImportFilter suppressing Boot's RedisAutoConfiguration + RedisReactiveAutoConfiguration
    so a service that ships this provider stays transport-agnostic.
pom.xml  (new)
  - esquire-tp-redis module; depends on esquire-common + spring-boot-starter-data-redis.
META-INF/spring.factories  (new)
  - registers TpRedisAutoConfigFilter as an AutoConfigurationImportFilter.
