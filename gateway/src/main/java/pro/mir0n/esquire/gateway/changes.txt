07/12/2026 mir0n  v1.2.11 -- the gateway's request log line carries correlationId as a FIELD (O1/T9)
filters.RequestTraceFilter
  - the INCOMING log line is wrapped in MDC.put/remove of PD_CORRELATION_ID and PD_REQUEST_ID, so correlationId is
    emitted as a log FIELD and not only as message text. The gateway is reactive, so the servlet MdcFilter never
    runs here; the put is safe because the log call is synchronous on this thread, and the remove is in a finally
    because a reactor thread is pooled and a leaked entry would stamp the next request

07/11/2026 mir0n  v1.2.11 -- business meters (O1/T8): the token relay -- cache hit rate and the KeyCloak round-trip
security.tokenrelay.TokenRelayCache
  - getOrAcquire() counts esq.biz.gw.tokenrelay.total (tag result = hit|miss). A GENUINE hit/miss: a hit serves
    the request without touching KeyCloak, a miss is a live /token round-trip on the hot path -- so the hit RATE
    is exactly how much of KeyCloak's latency the users are spared
security.tokenrelay.WebClientTokenRelayClient
  - acquire() counts esq.biz.gw.tokenrelay.acquire.total and times esq.biz.gw.tokenrelay.duration (tag outcome =
    ok|error|cancelled) around the KC /token call -- an EXTERNAL server on the hot path that nothing measured.
    Wrapped in Mono.defer so the clock starts at SUBSCRIPTION, not assembly: a nanoTime() outside the chain is
    captured when the Mono is BUILT and times the wrong window. doOnSuccess / doOnError / doOnCancel cover every
    terminal signal, so a client that hangs up mid-relay does not vanish from the count
resources/application.yml
  - esquire.observability.metrics.business-enabled: ${ESQ_METRICS_BUSINESS:true} added -- the sub-switch gating
    the esq.biz.* domain tier under the observability master

security/tokenrelay/  (new sub-package -- 10 files; replaces 8 prior parallel classes)
  - TokenRelayFilter: single WebFilter; iterates configured ITokenRelayVariant list; first
    variant returning Relay or Reject wins; cache lookup, KC call on MISS, Authorization
    header rewrite, chain dispatch
  - TokenRelayCache: ConcurrentHashMap<String, ExpiringJwt> keyed by variant-supplied
    cacheKey; shared by both variants
  - ITokenRelayClient + WebClientTokenRelayClient: single KC /token caller; takes
    KcTokenRequest (form params + Basic auth), returns ExpiringJwt
  - ITokenRelayVariant: SPI returning VariantAction sealed type (Pass | Reject | Relay)
  - VanillaTokenRelay: HTTP Basic at edge -> client_credentials grant; cacheKey = client_id;
    inbound-Bearer-with-azp-in-allowlist rejected with 401 (closes architectural-bypass gap)
  - PhantomTokenRelay: stripped Bearer at edge -> RFC 8693 token-exchange via confidential
    esq-gw-exchange client; cacheKey = source-token jti
  - KcTokenRequest, ExpiringJwt, VariantAction: shared records / sealed type
security.JwtClaimPeek  (new)
  - shared utility for peeking JWT azp / jti claims without signature validation;
    used by both Token Relay variants as a routing decision before the downstream JWS
    validator runs

security.JwksController

- security.IntrospectionAwareJwtDecoder  (REMOVED -- intermediate JWS+ design, superseded by Vanilla Token Relay)
- security.IntrospectionClient            (REMOVED)
- security.WebClientIntrospectionClient   (REMOVED)
